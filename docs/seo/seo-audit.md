# SEO Audit — Data Decision Consulting

Research date: 1 September 2026
Site audited: https://datadecision.consulting/ (live) and repository `datadecision-site` @ commit `edab826`, branch `codex/rebuild-v2` (research performed on new branch `seo/research-package`)
Auditor scope: full codebase inspection (Astro static build), live-site crawl of all template routes, sitemap.xml and robots.txt fetch, Google autocomplete capture for ~25 seed queries, DuckDuckGo SERP capture for priority queries, and review of existing internal research (`docs/content-opportunity-map.md`, 28 Aug 2026).

## 1. Executive summary

**Strengths (unusual for a new site):**

- 71 validated HTML routes, all with unique title tags, meta descriptions, exactly one H1, self-referencing canonicals, `index,follow` robots meta, and Open Graph/Twitter cards (`src/layouts/BaseLayout.astro`).
- Clean static architecture: Astro static output, directory-format URLs with consistent trailing slashes, `sitemap.xml` generated from the actual route list (`src/pages/sitemap.xml.ts`), sensible robots.txt with explicit AI-crawler policy.
- Organization / WebSite / Person (founder) / Article / Service / FAQPage / BreadcrumbList schema already present, driven from a single entity definition file (`src/data/entityDefinition.ts`) — this is the correct pattern and prevents entity drift.
- 44 substantive insight articles with dated publication/update metadata, source lists, methodology versions, and honest-limitation framing. Content depth in GA4/CRM reconciliation, demo-funnel diagnosis and AI-visibility measurement is genuinely strong.
- A build-time validation gate (`npm run validate`) enforces one H1, canonical presence, brand tagline, contact email, unique titles/descriptions (duplicate detection), internal-link integrity and claim guardrails. This is rare and valuable.
- Free browser tools and downloadable CSV templates exist — linkable assets most competitors lack.
- `npm run build` + `npm run validate` pass at baseline (71 files, 0 errors).

**Critical weaknesses (why non-branded visibility is near zero):**

1. **No page owns any commercial service query.** The site has zero URLs targeting "b2b saas seo agency", "ai seo agency", "seo agency for saas", "ga4 consultant", "website development and seo company" or any city-modified service query. All existing commercial routes describe _methodologies_ ("Measurement-first AI-search visibility for B2B SaaS"), not the _services buyers search for_.
2. **Positioning conflict (three-way).** See §3 — the homepage/title system says "measurement-first AI-search visibility for B2B SaaS" (narrow diagnostic consultancy), `/services/` says "complete digital growth engine… from building your website to SEO, AI search visibility, content, paid acquisition, conversion and analytics" plus AI agent development and GPT integrations (full-stack agency), while the entity definition and About say "Focused on AI-search visibility, measurement foundations and scoped implementation" (narrow again). Google receives three different businesses from one domain.
3. **Title-tag pattern buries the brand and misses intent.** Nearly every title is `Topic | Data Decision Consulting`. The brand segment consumes 25 characters on 45+ pages while no title contains a searchable service phrase ("agency", "services", "consultant", "company" appear almost nowhere).
4. **No geographic signal at all.** No city page, no service-area statement beyond `areaServed: 'Remote'` in one Service schema, no location mention anywhere in copy. For every commercial query that carries a city modifier, the site is ineligible on relevance grounds. Founder is NIT Surat-educated and the India ₹ budget article exists — India/Gujarat context is defensible; anything else is not (see §7).
5. **Insight content targets no searchable problem phrasing.** Titles like "Pricing-Page Visits Up, Demos Flat" are internal-symptom labels, not search queries. The articles answer real problems ("why is my website not ranking", "GA4 vs CRM counts disagree", "how to appear in ChatGPT recommendations") but never use the searcher's words in title/H1/intro.
6. **Zero external authority.** No Google Business Profile (not eligible — no staffed physical office confirmed), no Clutch/GoodFirms listing, no third-party reviews, no backlinks beyond the GitHub Pages infrastructure. The authority scorecard page honestly acknowledges this.
7. **Cannibalisation risk already present in the architecture:** `/ai-search/` (pillar) vs `/services/ai-search-visibility/` (service) vs `/insights/build-ai-visibility-baseline/` vs `/ai-search-observatory/` all discuss "AI-search visibility" with overlapping vocabulary. Currently rescued only by genuinely different page purposes; adding commercial targeting without a keyword-to-URL map would break this.

## 3. Positioning conflict analysis (Phase 1 requirement)

Direct comparisons from live pages and `entityDefinition.ts`:

| Source                                                              | Claimed identity                                                                                                                                                                          |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Homepage `<title>`, entity `description`, footer description, About | "Measurement-first AI-search visibility for B2B SaaS" — a narrow measurement/diagnostic consultancy                                                                                       |
| Homepage hero H1 + lede, `/services/` H1 + lede                     | "Complete digital growth engine — from building your website to SEO, AI search visibility, content, paid acquisition, conversion and analytics" — a full-service digital marketing agency |
| `/services/` blocks 05–06                                           | AI Agent Development + AI & GPT Integrations — an AI development/integration shop                                                                                                         |
| `entityDefinition.category`                                         | "Decision intelligence consultancy"                                                                                                                                                       |
| Four pillars + insights                                             | B2B SaaS growth/demand-gen/marketing-analytics education — consistent with SaaS focus                                                                                                     |

**Contradictions flagged:**

1. "Measurement-first AI-search visibility" (every meta surface) vs "we build the complete digital growth engine" (hero/services) — a diagnostic shop vs a do-everything agency. These recruit different buyers and Google cannot classify the domain.
2. Service breadth (6 services incl. website development, AI agents, GPT integrations) vs the entity's `oneLineFocus`: "Focused on AI-search visibility, measurement foundations and scoped implementation" — the schema says focused; the services page says broad.
3. `category: 'Decision intelligence consultancy'` appears nowhere in page copy — an internal label leaking into structured data.

**Recommended primary positioning (subject to founder approval — this is the single most important decision in the package):**

> **Data Decision Consulting is a B2B SaaS growth and SEO consultancy.** Two flagship commercial pillars: (1) **SEO & AI-search visibility** (SEO + AEO/GEO, incl. the visibility diagnostic), (2) **measurement & attribution (GA4/CRM)** — supported by paid acquisition, CRO and website development as _secondary_ services, and AI agents/integrations as tertiary services. B2B SaaS remains the declared focus market; select adjacent verticals (B2B manufacturing/export, professional services) are Phase-2 targets per the keyword data.

This keeps the existing evidence-rich SaaS foundation, aligns with the two service detail pages that already exist, and matches the strongest realistic keyword opportunities (see keyword-master.csv: "b2b saas seo agency", "saas seo agency in india", "ai seo agency", "ga4 consultant"). The full-service / AI-agent breadth stays on `/services/` as supporting lines rather than the identity.

## 4. Metadata system findings

- Titles: unique across all 71 files (validator-enforced). Pattern `Topic | Data Decision Consulting` — brand-first suffix is fine, but no page uses a searchable category phrase.
- Meta descriptions: unique, well-written, present everywhere.
- OG/Twitter: complete on all pages; `og:image` single default asset.
- Canonicals: self-referencing everywhere, absolute, correct trailing slash. ✅
- robots.txt: clean, sitemap referenced, deliberate AI-crawler policy (GPTBot/ClaudeBot/Google-Extended blocked for training; search/user bots allowed). Note: this is a **business choice already documented** in `/insights/ai-crawler-access-policy/`; keep.
- `llms.txt` present in `/public/` ✅.
- Sitemap: all 45 indexable URLs + 1 work record; `lastmod` for static routes is a hardcoded `2026-08-28` — should be updated on next change or derived per-file; minor.
- No `hreflang` (single language — correct to omit).
- Structured data all validates via the internal validator; matches visible content; no fake ratings anywhere. ✅ (Quality gate: verified no AggregateRating/Review schema in templates.)

## 5. Content and internal linking

- Navigation is crawlable static anchors ✅; breadcrumbs present on inner pages with BreadcrumbList schema ✅.
- Footer links every pillar, evidence page and utility page — crawl depth ≤ 2 for everything. No orphan pages. ✅
- Internal-link anchor text is generic in places ("Explore →", "Read the complete method") but mostly descriptive.
- Missing: links from insights to a commercial "services" owner for SEO/agency queries (none exists), and no links to industry- or city-level pages (none exist).

## 6. Performance / mobile (static build)

- Astro static HTML, inlined critical CSS, font packages with `fontsource` (self-hosted, no third-party font requests), vanilla-JS only, no animation libraries, `prefers-reduced-motion` honoured. Images: only `og-default.png`, `logo.png`, favicons — page weight is inherently low. No Core Web Vitals regressions expected from any copy change; keep the existing motion layer untouched per operating rule 15.
- Mobile: single-column `shell` layout, 320px-safe per prior QA; validator + manual spot-check found no issues. Any new pages must reuse existing layout components.

## 7. Local visibility (Phase 14 prerequisite finding)

- No verified physical office anywhere; the entity schema correctly uses `Organization` (not `LocalBusiness`). Founder based in India (NIT Surat alumni; ₹-denominated budget content; LinkedIn). **Do not create LocalBusiness schema or Google Business Profile** without a verified staffed address. City pages may only honestly say "remote SEO services for [city] teams" if evidence supports demand (see city-opportunity-analysis.csv).

## 9. Top-priority corrections (technical, before content)

All green at baseline — the technical foundation is ahead of most new sites. Only changes needed:

1. Title-pattern refresh on commercial pages (searchable service phrases).
2. Homepage repositioning (after founder decision in §3).
3. Sitemap `lastmod` automation for changed routes.

- Honest-claims framework, evidence labels, DEMONSTRATION RUN governance — these are conversion assets for a cautious buyer, not SEO baggage.
