Two teams quote different numbers for "pipeline generated by marketing". Both are correct. One uses first-touch, the other uses a weighted multi-touch model, and neither document says which.

The argument is not about data quality. It is about undocumented assumptions.

## The register format

One spreadsheet, five columns, one row per reported metric:

| Column           | What it records                             | Example                                  |
| ---------------- | ------------------------------------------- | ---------------------------------------- |
| Metric           | The reported number, exactly as labelled    | "Paid pipeline (Q3 dashboard)"           |
| Attribution rule | Credit model + window + source definition   | First-touch, 90-day, CRM original source |
| Assumption       | What must be true for the number to mean it | "Original source survives deal merges"   |
| Owner            | Who is accountable for verifying it         | RevOps lead                              |
| Last verified    | Date + method                               | 2026-08-12, test-deal walkthrough        |

The register is not documentation for its own sake. It is what lets a new CMO challenge a number in week one instead of trusting it for a year.

## The assumptions most B2B teams carry silently

- **First-touch wins:** assumes the first recorded touch deserves the credit.
- **Last-touch wins:** assumes the closing touch caused the deal.
- **Window is right:** assumes 30/90 days matches the actual buying cycle.
- **Source survives:** assumes CRM fields are not overwritten by later activity or merges.
- **Offline is included:** assumes every deal path enters the CRM the same way.

None of these are wrong. All of them are invisible until written down.

## How to run the first verification

Pick one metric the board sees. Walk one real deal through the systems and record what each field contains at each stage. Compare what you observe against the attribution rule in the register. Note every place the observed path differs from the assumed one.

That walkthrough usually produces one of three outcomes: the rule is confirmed, the rule is corrected, or the metric is renamed to describe what it actually measures.

## Decision rules

- If two reports must coexist, both belong in the register with different names.
- If an assumption cannot be verified, label the metric directional.
- If the owner leaves, the register names their successor before the next report ships.
